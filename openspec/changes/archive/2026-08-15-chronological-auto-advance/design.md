# 設計: 自動連続再生の時系列順化

## Context

再生キューは明示的なキューを持たず、「フィルター適用後の一覧の並び順=再生順」という規則で
`logic/PlaybackQueue.playbackOrderFrom` が事前に組み立て、`PlaybackConnection.play` が
Media3 に `setMediaItems` で丸ごと渡す。一覧の並びは `EpisodeDao` の
`ORDER BY publishedAtEpochMillis DESC, id DESC`(新しい順)なので、自動継続は新→旧に遡る。
利用者の運用は「残っている中で一番古い回から聴き、新しい回へ進む」であり、向きが逆。

呼び出し側は 2 箇所(`EpisodeListViewModel.play` / `EpisodeDetailViewModel.startPlayback`)。
どちらも同じフィルター適用後リストを渡すため、規則の変更は `PlaybackQueue` に閉じる。

なお `PlaybackQueue.nextAutoPlayable` は事前組み立て方式への移行後 main から呼ばれておらず、
テストの中でだけ「同じ解釈の別表現」として生きているデッドコード。

## Goals / Non-Goals

**Goals:**

- 自動連続再生を時系列順(古→新)にする。開始エピソードを鳴らし終えたら、それより新しい
  DL済みエピソードへ進み、最新まで達したら停止する
- 一覧の表示順(新しい順)は変えない
- 未DLスキップ・自動DL禁止・終端で停止という既存の約束を維持する
- デッドコード `nextAutoPlayable` とそのテストを削除する

**Non-Goals:**

- 並び順の設定・切り替え UI(設計思想により作らない。向きはコードが規定する)
- 開始エピソードより古い回のキュー投入(運用上、開始点は常に「残りの最古」なので不要)
- 一覧表示のソート変更、明示的なキュー管理機能

## Decisions

### D1: 一覧は新しい順のまま、キューの向きだけ反転する

`playbackOrderFrom` を「開始エピソード + リストでそれより**上**(新しい方向)のDL済みを
古→新の順」に変える。実装は `episodes.take(startIndex + 1).reversed().filter { it.downloaded }`
相当(開始エピソードが未DLなら従来どおり空を返すガードは維持)。

- 代替案A: DAO の `ORDER BY` を ASC にして「リスト順=再生順」の不変条件を守る —
  却下。回数の多い番組で一覧の先頭が最古回になり、新着確認のたびに最下部への
  スクロールを強いる。表示体験の犠牲が大きい
- 代替案B: 番組ごとに並び順を切り替え可能にする — 却下。「機能を増やさないことが機能」
  に反する(Podcast Addict 化の第一歩)

これにより設計上の規則は「画面の並び順=再生順」から「画面の並び順の**逆**(=時系列順)=
再生順」に変わる。規則としての単純さ・決定論性は保たれる(UI 上は再生中アイコンが行を
上へ移っていく)。

### D2: 開始エピソードより古い回はキューに含めない(一方通行)

利用者は「残っている中で一番古い回」から再生を開始する運用のため、開始点より古い側へ
戻る経路は不要。含めると「途中の回をタップしたら過去回が末尾に回り込む」という
説明しづらい挙動になるため、単純な一方通行を選ぶ。

### D3: 時系列順の実体は「リスト順の逆転」として実装する

`playbackOrderFrom` は受け取ったリストの並びを信頼し、`publishedAt` を直接見ない。
「時系列順」が成立するのは一覧が新しい順(`publishedAt DESC, id DESC`)である前提に
依存する。この前提は KDoc に明記する。同時刻公開(タイムスタンプ同値)の回は
リストの逆転により id 昇順で鳴る — 決定論的で、投入順とも一致する。

- 代替案: `PlaybackQueue` 内で `sortedBy { publishedAt }` する — 却下。並び替え規則が
  DAO と logic の 2 箇所に分かれ、フィルターとの整合(「一覧に出ているものだけが対象」)も
  自前で再現することになる。リストを唯一の正とする現行構造を守る

### D4: `nextAutoPlayable` は削除する

main から未使用。git に履歴が残るため復活は容易で、残す方が認知負荷(「どちらが本物の
規則か」)を生む。`PlaybackQueueTest` の該当ケースと、`PlaybackQueuePropertyTest` の
`nextAutoPlayable` を使うプロパティも削除する。

残る property テストは `playbackOrderFrom` 単独の不変条件として再定義する:

1. 結果が空でなければ先頭は必ず開始エピソード
2. 結果はすべてDL済み
3. 結果は「入力リストを逆順にした列」の部分列(相対順序の保存 = 古→新)
4. 開始エピソードが未DLまたはリストに不在なら空

## Risks / Trade-offs

- [「時系列順」が DAO のソートに暗黙依存] → D3 のとおり KDoc に前提を明記。DAO の
  `ORDER BY` を変えれば再生順も変わるが、単一利用者・単一コードベースでは
  「ソートを変えたら再生順も変わる」はむしろ期待どおりの連動
- [聴取途中の回が複数あるとき、開始点より古い残りはキューに入らない] → 仕様どおり
  (D2)。聴き残しは一覧(未聴フィルター)で見えるため、見失うことはない
- [spec の要件名変更に伴う archive 時の突合せ] → 旧要件「リスト順の自動継続再生」は
  REMOVED、新要件「時系列順の自動継続再生」は ADDED として delta を書き、
  取り違えを避ける

## Migration Plan

データ移行なし(DB スキーマ・保存データに変更なし)。`./gradlew installDebug` の
上書きインストールのみ。切り戻しはコミットの revert で完結する。
