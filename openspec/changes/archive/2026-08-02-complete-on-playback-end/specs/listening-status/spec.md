# listening-status Delta

## MODIFIED Requirements

### Requirement: 再生完了による自動視聴済み判定
エピソードが実際に末尾まで鳴り終わったとき(次のエピソードへの自動遷移、またはキュー末尾での再生終了)、そのエピソードを自動的に視聴済みにするものとする(SHALL)。再生位置にもとづく早期判定(残り時間の閾値)は行わない(MUST NOT)。

#### Scenario: 末尾まで鳴り終わって次のエピソードへ進む
- **WHEN** エピソードが最後まで再生され、次のDL済みエピソードへ自動遷移する
- **THEN** 鳴り終わったエピソードは視聴済みになる

#### Scenario: キューの最後のエピソードを聴き終える
- **WHEN** キュー末尾のエピソードが最後まで再生される
- **THEN** そのエピソードは視聴済みになる

#### Scenario: 終端直前で停止した場合は未聴のまま
- **WHEN** エピソードを終端の数秒前で一時停止し、再生を再開しない
- **THEN** エピソードは未聴のまま残る(再開して鳴り終えれば視聴済みになる。手動トグルでの視聴済み化も可能)

#### Scenario: 長さ不明のフィードでも自動判定される
- **WHEN** 長さ(duration)を申告しないフィードのエピソードを最後まで再生する
- **THEN** エピソードは視聴済みになる(イベントベースの判定は長さ情報に依存しない)

### Requirement: 視聴済みファイルの自動削除
エピソードが視聴済みになったとき、favoriteでなければDL済みファイルを自動削除するものとする(SHALL)。削除後もDB上のエピソード記録とenclosure URLは保持し、再DLを可能とする。favoriteのエピソードのファイルは削除しない。favoriteカラムはMVPではデータモデルにのみ存在し、UIは設けない。

#### Scenario: 自動判定経由の即時削除
- **WHEN** 再生完了(実際に末尾まで鳴り終わったこと)で視聴済みになる
- **THEN** DLファイルは即時削除され、エピソードは未DL状態に戻る(DB記録は残る)

#### Scenario: favoriteエピソードの保護
- **WHEN** favorite = true のDL済みエピソードが視聴済みになる
- **THEN** ファイルは削除されない
