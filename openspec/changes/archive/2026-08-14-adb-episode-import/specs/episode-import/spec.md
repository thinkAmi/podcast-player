# episode-import Delta Specification

## ADDED Requirements

### Requirement: adb 経由の既存購読へのエピソード取り込み
USB デバッグを許可した PC から、`run-as` 配下の `am broadcast` で `feed_url`(取り込み先の購読フィード URL)と `import_url`(アーカイブ XML の URL)を届けることで、既存購読へエピソードを取り込めるものとする(SHALL)。取り込みは購読済みのフィードに対してのみ行い、`feed_url` が未購読の場合は何も保存せず失敗を返すものとする(SHALL。勝手に購読登録しない)。取り込まれたエピソードは通常のエピソードと等価に扱われ、一覧では公開日時順の該当位置に並ぶものとする(SHALL)。この経路のためのアプリ内 UI・設定は追加しない(MUST NOT)。`import_url` extra を含まない従来の broadcast は、現行どおり購読登録として処理するものとする(SHALL)。

#### Scenario: アーカイブ XML の取り込み
- **WHEN** PC のスクリプトが購読中のフィード URL と、その購読向けアーカイブ XML の URL を届ける
- **THEN** アーカイブ内のエピソードが当該購読に追加され、結果として取り込み件数(総数と新規数)が PC へ返り、一覧では公開日時順に既存エピソードと混ざって表示される

#### Scenario: 未購読フィードへの取り込み指示
- **WHEN** 購読していないフィード URL を `feed_url` に指定して broadcast を届ける
- **THEN** 購読もエピソードも保存されず、未購読であることを示す失敗が返る

#### Scenario: 従来の購読登録 broadcast との後方互換
- **WHEN** `import_url` extra を含まず `feed_url` のみの broadcast が届く
- **THEN** 現行仕様どおり購読登録として処理される(取り込みモードには入らない)

#### Scenario: 空または欠落した import_url extra
- **WHEN** `import_url` extra が空文字・空白のみの broadcast が届く
- **THEN** 取り込みモードとして扱わず、`feed_url` のみの broadcast と同じ挙動になる

### Requirement: 出典宣言による誤注入防止
取り込み対象の XML は、全 item が RSS 2.0 標準の `<source url>` 要素(出典宣言)を持ち、その url が全 item で同一であり、かつ取り込み先購読の feedUrl(購読登録時の文字列)と trim 後に完全一致する場合に限り取り込むものとする(SHALL)。宣言の欠落・値の混在・不一致が 1 item でもあれば、全体を拒否し部分取り込みを行わない(MUST NOT)。拒否理由(宣言なし・混在・不一致・未購読)は区別して PC 側へ返すものとする(SHALL)。

#### Scenario: 出典宣言のない XML の拒否
- **WHEN** `<source>` を持たない通常の RSS(公式フィード自身を含む)を `import_url` に指定する
- **THEN** 取り込み用アーカイブではないとして全体が拒否され、エピソードは 1 件も追加されない

#### Scenario: 別番組の購読への誤注入の拒否
- **WHEN** アーカイブ XML の出典宣言と異なるフィード URL の購読を `feed_url` に指定する(引数ペアの取り違え)
- **THEN** 不一致として全体が拒否され、エピソードは 1 件も追加されない

#### Scenario: 出典宣言が混在する XML の拒否
- **WHEN** item ごとに異なる `<source url>` を持つ XML を取り込もうとする
- **THEN** 混在として全体が拒否され、エピソードは 1 件も追加されない

#### Scenario: 宣言が一致する正しいペアの取り込み
- **WHEN** 全 item の `<source url>` が取り込み先購読の feedUrl と完全一致する XML を取り込む
- **THEN** 検証を通過し、エピソードが取り込まれる

### Requirement: 取り込みの不変性と冪等性
取り込みはエピソードのみを対象とし、購読のメタデータ(タイトル・アートワーク・feedUrl)を変更しない(MUST NOT)。既知の guid のエピソードの状態(視聴済み・DL・再生位置)は変更しない(MUST NOT)。`import_url` は永続化せず、以後のフィード更新でアーカイブ XML への通信を発生させない(MUST NOT)。同一 XML の再取り込みは guid に基づき冪等であるものとする(SHALL)。

#### Scenario: 購読メタデータの保持
- **WHEN** channel タイトルが購読中の番組名と異なるアーカイブ XML(例: 「〜過去回アーカイブ(非公式)」)を取り込む
- **THEN** 購読一覧・エピソード一覧の番組名とアートワークは変わらない

#### Scenario: 再実行の冪等性
- **WHEN** 同じアーカイブ XML を 2 回取り込む
- **THEN** 2 回目の新規件数は 0 で、エピソード総数・各エピソードの状態は 1 回目の完了時と同じになる

#### Scenario: 取り込み後のフィード更新
- **WHEN** 取り込み完了後にフィードを手動更新する
- **THEN** 通信は購読フィード URL に対してのみ発生し、取り込み済みエピソード(現行フィードに存在しない guid)はそのまま残る

### Requirement: 出典宣言の読み取りと通常経路の互換性
RSS パーサーは item の `<source>` 要素の url 属性を読み取れるものとする(SHALL)。購読登録・フィード更新の通常経路は出典宣言を検証に使わず、`<source>` の有無・値によって挙動を変えない(MUST NOT)。

#### Scenario: 出典宣言付きフィードの通常購読
- **WHEN** `<source>` 付きの XML(アーカイブ XML など)を通常の購読登録で登録する
- **THEN** 従来どおり新しい番組として購読され、エピソードが取り込まれる(出典検証は行われない)

### Requirement: PC 側取り込みスクリプトとスキル
取り込みコマンド(コンポーネント名・extra キー・クォート処理という契約)はリポジトリ内のスクリプトに一元化するものとする(SHALL)。スクリプトは第 1 引数を取り込み先の購読フィード URL、第 2 引数をアーカイブ XML の URL とし、双方が https であることの早期検証・adb 接続とアプリ存在の前提チェックを行い、Receiver が返した結果コードと結果データをそのまま報告するものとする(SHALL)。AI からの実行はスキルを経由し、adb コマンドを即興で組み立てないものとする(SHALL)。スキルは実行前に (1) 渡すべき引数とその意味の明示、(2) アーカイブ XML の要約(item 件数・出典宣言・最初と最後のタイトル)を利用者へ提示して承認を得ることを必須とし、承認なしに実行しない(MUST NOT)。

#### Scenario: スクリプトによる取り込み
- **WHEN** 取り込みスクリプトを正しい引数 2 つで実行する
- **THEN** broadcast が配達され、スクリプトは Receiver が返した取り込み結果(件数または拒否理由)を報告して終了する

#### Scenario: 前提が満たされていない実行
- **WHEN** 端末未接続・引数不足・https 以外の URL でスクリプトを実行する
- **THEN** broadcast を送らずにエラーメッセージを表示して終了する

#### Scenario: スキルの実行前確認
- **WHEN** 利用者が AI に取り込みを依頼する
- **THEN** AI は引数 2 つを確定させ、アーカイブ XML の要約と取り込み先を提示して承認を求め、承認が得られた場合のみスクリプトを実行する

#### Scenario: 承認が得られない場合
- **WHEN** 実行前確認で利用者が承認しない、または出典宣言と取り込み先の食い違いが見える
- **THEN** スクリプトを実行せず、状況を報告する
